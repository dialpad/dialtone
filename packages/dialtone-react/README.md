# @dialpad/dialtone-react

Dialtone's React components, ported from `dialtone-vue`. Private for now.

## Commands

Run these from the repo root. Each builds what it needs first (dialtone-icons, dialtone-tokens).

| Command | What it does |
| --- | --- |
| `pnpm nx run dialtone-react:lint` | ESLint (`eslint.config.js`): typescript-eslint and the Rules of Hooks for `.ts`/`.tsx`, the repo's style rules for everything. Commits also lint their staged files (husky, `.lintstagedrc.cjs`) unless husky is skipped; the gate's Lint row and CI's `check` job catch lint errors either way. |
| `pnpm nx run dialtone-react:typecheck` | `tsc` over the whole package. |
| `pnpm nx run dialtone-react:test` | Vitest, every `*.test.ts(x)` in `common/`, `components/`, `icons/` and `tests/`. DOM parity's tests (`parity/react/dom.test.tsx`, `parity/vue/goldens.test.js`) run in the gate, each with its own Vitest config, and `parity/vue/transition-traces.test.js` runs only by hand, to re-record DtTransition's traces. |
| `pnpm nx run dialtone-react:build` | The library: ES modules and type declarations in `dist/`. Entry points: `@dialpad/dialtone-react`, `@dialpad/dialtone-react/components/<Name>` and `@dialpad/dialtone-react/icons`. React, React DOM and every runtime dependency stay external. |
| `pnpm nx run dialtone-react:gate -- <unit>` | The parity gate for one unit, by id: `-- validation-messages` checks `components/ValidationMessages/`. A directive, mixin or composable unit lives in `common/`, under its id without the prefix: `-- mixin-input` checks `common/input/`. |
| `node --test 'packages/dialtone-react/parity/*.test.mjs'` | The harness's own tests: which units CI gates for a change (`parity/changed-units.mjs`), which Vue tests a unit has (`parity/vue-sources.mjs`), how DOM parity serializes select options (`parity/normalize.mjs`), that the gate fails a unit dialtone-vue has no source for (`parity/gate.mjs`), and which of a unit's gate failures in CI its base already had (`parity/new-failures.mjs`). |

Generated, gitignored files: `index.ts` (the barrel, `scripts/build-index.mjs`, from every `components/*/index.ts` and `common/*/index.ts` plus Vue's public common modules) and `icons/generated/` (`scripts/build-icons.mjs`). Build, typecheck, test and gate regenerate both; run `pnpm --filter @dialpad/dialtone-react generate` after adding a component if your editor needs the barrel.

Shared test helpers ported from dialtone-vue are in `tests/helpers/`: `validation_messages`, `clipboard` (`simulatePaste`; `tests/setup.ts` installs the same `ClipboardEvent` and `DataTransfer` stand-ins Vue's setup does), `fixtures` (`EmptyComponentFixture`) and `node_traversal`. Two more stand in for what Vue Test Utils does by itself: `transition` (`finishTransitions`, as VTU stubs `<transition>`) and `link` (`RouterLinkStub`, `withRouterLink`).

Foundations every port shares, in `common/`: `localization` (`DialtoneLocalization`, `useI18n`, `DtLocalizationProvider`, on `@fluent/bundle` over dialtone-vue's `.ftl` files), `link` (`DtLinkProvider`, `useLinkComponent`, `DtRouterLink`, for `to`) and `transition` (`DtTransition`, Vue's `<Transition>`; its tests replay Vue's recorded traces in `parity/transition-traces.json`).

## Storybook

Run these from the repo root.

| Command | Serves | What it is |
| --- | --- | --- |
| `pnpm nx run dialtone-react:storybook:all` | 9011, 9012, 9013 | Starts Vue's, React's and the comparison Storybook together. Open http://localhost:9013. |
| `pnpm nx run dialtone-react:storybook` | http://localhost:9012 | React's Storybook alone. It mirrors Vue's: same themes, toolbars, addons and sidebar order. |
| `pnpm nx run dialtone-react:storybook:compare` | http://localhost:9013 | The comparison alone. It needs Vue's Storybook (`pnpm nx run dialtone-vue:start`) and, for the React side, React's. |
| `pnpm nx run dialtone-react:typecheck` | | Typechecks the package, both Storybook configs included. |

`storybook:all` first checks that ports 9011, 9012 and 9013 are free, and exits with a message naming the taken ones if not (e.g. another checkout's Storybook is running). It builds dialtone-css, dialtone-icons, dialtone-tokens and Vue's `build-functions`, then runs Vue's own `start` target, which rebuilds those packages when they change. The React Storybook generates the React icons (`scripts/build-icons.mjs`) before it starts, and its own target rebuilds dialtone-css and dialtone-tokens when they change. The comparison starts once Vue's story index answers (it waits up to 10 minutes), which takes a minute or two on a cold start.

**Stopping.** Press Ctrl-C in the terminal that runs the command: it stops every Storybook and watcher it started. Killing only the parent process (e.g. `kill <pid>` on the top `nx`) leaves the nested `nx watch` and `nx run dialtone-vue:start` processes running, still holding their ports; find them with `lsof -nP -iTCP:9011-9013 -sTCP:LISTEN` and `pgrep -fl "nx watch"`, and kill them by PID.

### The comparison

- **Sidebar.** `compare/generate-stories.mjs` reads Vue's `index.json` and writes one story per Vue story into `compare/generated/` (gitignored), with the same title and export name, so the sidebar and every generated story's id match Vue's. It skips any Vue story it can't reproduce (no export name, an export name that isn't a plain identifier, or one that doesn't give Vue's id) and lists those in its output. It runs each time the comparison starts. Restart the comparison to pick up stories added to Vue since.
- **Frames.** Each story shows Vue's and React's preview of the same story id side by side. The React side says "Not ported yet" when React's Storybook has no story with that id. If React has stories under the same component id, title or story file name, it lists them ("React has: …"): a ported story with a wrong title or export name shows up there. The generator also logs every React story id Vue doesn't have, when React's Storybook is up by then.
- **Hidden stories.** A Vue story hidden from the dev sidebar (`tags: ['!dev']`) is hidden in the comparison too.
- **Theme.** The Theme and Contrast toolbars go into both frames' URLs. The dark-mode toggle is sent to each frame when it renders.
- **Args.** The controls under the frames are the Vue story's (its argTypes and initial args, as Vue's preview reports them). A change reloads both frames with the same URL args.
- **Sync.** The Sync toolbar (off by default) mirrors one frame's input in the other: hover, click, scroll or type in either frame and the other frame gets the same. It stays in the URL (`globals=compareSync:on`), and isn't passed to the frames. The frame the pointer was last in, or the last key or typing, is the source; the chip in the Vue pane's header says which way it mirrors ("Mirroring Vue → React"), or why sync is off: React has no story or isn't running, or a frame didn't answer the handshake (a Storybook built before sync mode has no agent). Over the other frame, a phantom cursor labelled with the source's name shows where the pointer is, pressed while the button is down; it's drawn by the comparison page, never in the story. What's mirrored: pointer movement, replayed as the enter, over, leave and out events along the element's ancestors (so hover-driven components like Tooltip open on both sides), presses and clicks (pointerdown, mousedown, pointerup, mouseup, click, each when it happens), drags (the moves between a press and its release carry the button, and a component that takes pointer capture, like Slider's track or Resizable's handle, keeps getting them), and scroll in pixels, clamped to the other side: the page's, and that of an element inside the story (a Combobox listbox, the Scroller), which is found in the other frame by a point inside it (the real pointer when it's there) and its closest scrolling ancestor, so a wrapper one framework adds doesn't matter. Only real input is sent, so nothing echoes back. In the other frame, a replayed click draws a ring at the phantom cursor, and a replayed scroll shows a thin bar, with a chevron once the direction is known, at that frame's end edge for a second; under reduced motion both stay still for their time.
- **Keyboard and focus in sync.** Named keys (Escape, the arrows, Home, End, Page Up and Down, Backspace, Delete, and Enter in a text field), with their modifiers, are replayed on the other frame's counterpart of the focused element. The counterpart is found by its place among the focusable elements with the same role, `data-qa` and accessible name, or else the nearest of them, or else the focusable element at the same point, so wrappers one framework adds don't matter. That drives Combobox (arrows, Enter, Escape) and Dropdown (arrows and Escape) in both frames. Typed text isn't replayed as keys: when a text field, a plain contenteditable, a select or a range input changes, its new value is copied into the other frame's field with the native value setter and an `input` event (and `change` for a select), which Vue's `v-model` and React's controlled inputs take as typing. Password fields are never mirrored. Real keyboard focus stays in the source, the frame of the last real press, key or typing. While a frame is the other one (the mirror), its `focus()` does nothing, so a component that focuses itself on a replayed click (Dropdown's menu, Slider's thumb) can't take focus from you. Instead, a dashed magenta ring, drawn by the comparison page over the frame, shows where its focus would be: on the counterpart of the source's focused element, or where its own component tried to move it. `focus()` is put back when that frame becomes the source again or sync turns off. At the bottom of the mirror's pane, the last few keys it got (`Escape`, `Shift+ArrowDown ×3`) show for 1.5 seconds; typed text shows as "typing…", never the text. Under reduced motion they don't fade.
- **Hover styles in sync.** The browser's `:hover` follows only the real pointer, so on its own the mirror shows no hover style. While sync is on, each preview copies every style rule that has a `:hover` into a stylesheet of its own, with `:hover` rewritten to a `data-dt-sync-hover` attribute (`:not(:hover)` to its absence), inside the same `@media`, `@supports`, `@layer`, `@container` and `@scope` rules as the original, and a nested rule inside its parent. The copy is a constructed sheet in `document.adoptedStyleSheets`, so the page's own sheets are never changed. The mirror puts the attribute on the element under the phantom cursor and all its ancestors (and on a hovered label's control), as `:hover` would apply, and takes it off as the pointer leaves, when the real pointer comes into that frame, and when sync turns off, which also takes the sheet out. It's an attribute, not a class, because Vue and React rewrite `class` when they re-render, as a Dropdown item does when the pointer highlights it. The copy is built in idle time after the handshake (in the Button story, about 1,450 rules copied out of 7,800, 17 to 21 ms of work in three to five slices, with no long task), and rebuilt when a style element or stylesheet link is added, changed or removed, or a sheet gets rules through `insertRule`. Each build is logged at the console's verbose level.
- **Sync agent.** Each preview runs `packages/dialtone-vue/.storybook/compare-sync-agent.js`: Vue's `preview.js` and this package's `.storybook/preview.tsx` both install it, as they share Vue's `theme-controller.js`. It does nothing until the comparison page sends its handshake (only a `message` listener, which ignores everything else, no DOM, no input listeners and no `focus()` shim), and talks to the page only through `postMessage` under its own key, so it works for the local dev servers (one origin each) and the published bundle (one origin) alike. `compare-sync-hover.js`, next to it, is the hover styles' part. `compare/sync.ts` is the page's side; `compare/SyncCursor.tsx` the cursor, `compare/SyncFocusRing.tsx` the fake focus ring and `compare/SyncKeys.tsx` the mirrored keys.

### Limits

- **What a URL can carry.** Storybook only accepts URL args that are numbers, booleans, colours, `undefined`, or strings of letters, digits, spaces, `_` and `-`. So a text value with punctuation (e.g. "Hello, world.") can't be set from the comparison; the control says so and keeps the frames as they are. Select options that a URL can't carry (e.g. Popover's `initialFocusElement` `#content-close`) are disabled and labelled. Object, array and function args aren't editable here at all; both frames keep the story's own value.
- **Args a frame drops.** After each reload, the controls list any changed arg a frame didn't apply. Storybook drops a URL arg the story doesn't declare (e.g. a slot arg renamed in React), or one whose type it can't map: a React prop typed `X | null` is a `union` to Storybook, so a URL value for it is dropped unless the story's argTypes give it a plain type. A story can also ignore an arg it gets (Vue's Text Default ignores `default` from the URL).
- **Reloads.** Every args change reloads both frames, so story state (an open tooltip, typed text) resets, and sync reconnects (the chip says "connecting" for a moment). Dark mode reaches a frame just after it renders, so a dark frame may flash light first.
- **What sync doesn't mirror.** A replayed key runs a component's key handlers and nothing else, so what only the browser does with a key isn't mirrored: Tab moving focus (Tab isn't sent; the mirror's ring follows the source's focus instead), characters typed as keys (text arrives as the field's value), IME composition, and Enter or Space activating a focused button or toggling a checkbox (neither those keys nor the click they make are sent, so the mirror's control doesn't fire: use the pointer to mirror it). Nothing is really focused in the mirror, so navigation that follows the browser's focus (Tab order, a radio group's arrows, anything that reads `document.activeElement`) doesn't move there; Dropdown's and Combobox's arrows do, as they keep their own highlight, and the ring shows where focus would go. Rich text editors (a contenteditable with markup, such as RichTextEditor) and multiple selects aren't copied. `autofocus`, `dialog.showModal()` and `window.focus()` aren't shimmed. Before the first press, key or typing, neither frame is the mirror. A drag is only the pointer events of one: no text selection, no native drag and drop (a synthetic event can't start either), no native range input or scrollbar drag (a range input's new value is copied, though), and an element that asks for pointer capture later than the event that pressed gets the browser's own refusal. Double-clicks aren't mirrored as such (two clicks are).
- **Hover styles' limits.** The copied rules come after all of the page's sheets, so a copied hover rule can win over a later rule of the same specificity (and layer) that would win under a real hover; none of the elements compared so far showed it. A rule in an anonymous `@layer` lands in a new anonymous layer. A sheet a script can't read (another origin's) isn't copied, and the build's log says how many were skipped. A style for the element that isn't hovered (`:not(:hover)`) can't be taken off without changing the page's own rule, so it stays on the mirror's hovered element, and a hover on a pseudo-element (`::-webkit-scrollbar-thumb:hover`) isn't copied. `:active`, `:focus`, `:focus-visible` and `:focus-within` aren't emulated, and neither are shadow roots' sheets.
- **Ports.** They are fixed in `compare/ports.json` and in the Nx targets. React's and the comparison Storybook exit if their port is taken (`--exact-port`). Vue's own `start` target would move to another port instead, which is why `storybook:all` checks all three ports before it starts anything. Run on its own, `storybook:compare` frames whatever answers on 9011 and 9012.
- **Vue's watcher loops.** Vue's `start` target (which `storybook:all` runs as is) watches dialtone-icons, whose `pre-build` rewrites `src/keywords-*.json`, which the watcher sees as a change. So under `storybook:all` it rebuilds dialtone-icons and dialtone-icons-vue over and over. The Storybooks keep working, but the log scrolls with builds. React's `storybook` target doesn't watch dialtone-icons (React's icons come from `scripts/build-icons.mjs`, not its build output), so it doesn't loop; restart it to pick up changed icons.

### Published previews

CI publishes all three Storybooks as a preview (`.github/workflows/dialtone-react-storybook.yml`) on a push to `dialtone-react`, and on a PR into it, that changes this package, Vue's sources, the css, icons, emojis or tokens packages, Combinator's sources, the lockfile, the setup action or the workflow itself. A change outside those paths gets no preview and no comment, and its PR keeps the one it had:

| Where | Folder |
| --- | --- |
| A PR into `dialtone-react` | `https://dialtone.dialpad.com/deploy-previews/react/pr-<number>/` |
| The `dialtone-react` branch | `https://dialtone.dialpad.com/deploy-previews/react/dialtone-react/` |

Each folder holds `react/` (this package's Storybook), `vue/` (Vue's, built from the same commit) and `compare/` (the side-by-side one, whose frames are the `react/` and `vue/` folders next to it). `build.json` in the folder names the commit and the time of the build. A PR gets a comment with the links once the upload has finished. Only Dialpad members publish, and a PR from a fork doesn't. `dialtone-react-storybook-clean.yml` removes a PR's folder when it closes, merged or not. GitHub doesn't run it for a PR with a merge conflict, so a conflicted PR closed unmerged keeps its folder until someone removes it by hand.

To build the same bundle locally: `pnpm nx run dialtone-react:build-storybook:compare`, then serve `storybook-static/` (React), `../dialtone-vue/storybook-static/` (Vue) and `storybook-static-compare/` as `react/`, `vue/` and `compare/` of one folder.
