# Selected documentation examples

Keep runnable source in its authored VuePress page. A selected live fence has a stable `<!-- example-id: examples/name -->` marker immediately before it and assembly metadata in `packages/dialtone-docs/src/generators/documentation-examples.mjs`. Imports describe setup, not discovery subjects: component subjects come from authored page associations; utility subjects name exact classes. Do not infer relevance from every imported layout component.

Use `vue-app` for the supported Vue setup and `static-html` for authored HTML without Vue tags, bindings, scripts or handlers. Selected state must come from the source; the current stateful cohort supports its authored `ref(false)` declaration. Unsupported setup needs an explicit disposition, not invented imports or copied unrelated page scripts. Static utility output supplies HTML plus CSS/theme prerequisites, not an application scaffold.

Run `pnpm nx run dialtone-docs:build` and inspect `packages/dialtone-docs/dist/example-coverage.json`. It reports source candidates, live/display twins, delivered IDs, remaining work and exclusions. Complete Loader/Toggle pages and a first utility example do not establish complete corpus coverage. Scratch sources are excluded; MDX marker support and other referenced/contextual forms remain explicit gaps. Migration, command and historical snippets retain their context.

For additions, renames or removals, update markers, assembly metadata and routes together. A selected source cannot disappear silently: retire or replace its definition deliberately and verify exact retrieval/no-match. Component/API, source-state, dependency or delivered-file changes require regenerated data and affected consumer checks. Whole-page hashes are provenance; unrelated page prose alone does not invalidate identical delivered files and runtime tuples. A recent date or a touched file is not evidence of semantic review.

Use `node scripts/retrieval/validate-examples.mjs <isolated-output-directory>` for the actual pinned consumer build/API or static CSS checks, then the packed adapter probe. Preserve unverified/pending results when evidence is absent. A build is not a browser, keyboard or screen-reader review, and source-faithful fixtures may still need application behavior or accessibility repair. Record manual evidence only when supplied and tied to the tested payload/profile.

Check the owning build/cache/CI inputs and shared lookup release policy for newly consumed sources. Generator/helper and source-only edits must reach the appropriate published adapters; a local build or site deployment does not update installed tools. Each change owns relevant contributor guidance and both public-guide updates. Keep coverage backlog and source-to-prose review separate from generated-output and release checks.

## Combinator presets

`dialtone-combinator:generate-examples` materializes the curated registry using the UI's serializer and binding logic. Documentation consumes only its ignored `.generated/preset-examples.json`; stale source/input hashes fail the build. There is no separate preset publishing list. New registered presets are evaluated on the next build; unregistered files are not enrolled.

Inspect `packages/dialtone-docs/dist/preset-example-coverage.json`. It accounts for delivered sources, unresolved context, policy exclusions and deprecation, with separate consumer-verified and unverified totals. A safely assembled fixture can be retrieved without consumer proof; it stays unverified. Missing state or unsupported APIs keep the affected source unresolved without suppressing other fixtures. Corrupt intermediate data still fails clearly.

Preset IDs encode exact component/preset names. Renames/removals retire old IDs, which use normal no-match recovery; no parallel retirement catalog or aliases are required. Copying a fixture supplies no application update handlers or persistence. Rebuild owning Vue/icon metadata and regenerate after source/default/support changes. Revalidate changed payload/profile bindings; unchanged matching proof can be reused. Use the validator's explicit `--id` selection and `--promote` option described in [the validation workflow](../../scripts/retrieval/README.md#selected-example-consumer-and-packed-delivery-checks). Machine results never create human accessibility evidence. Register producer changes with the shared lookup release policy before publication, then verify packed delivery. Installed tools need package updates; MCP also needs a restart.
