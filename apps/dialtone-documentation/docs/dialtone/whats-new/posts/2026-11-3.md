## At a glance

- [DtSlider](/components/slider.md) is the new Dialtone component for selecting a single value or a range of values along a scale. It supports horizontal and vertical orientations, marks, ticks, snapping, and `start` and `end` slots.
- It's built on the native `<input type="range">` (one per thumb), making it accessible by default (including keyboard, focus, form, and screen reader behavior).
- The value appears in a _tooltip_ by default, which doesn't reserve any space and can't be clipped by a parent container. Other options are provided.
- `step` is a hard grid, while `snapPoints` is a soft, _magnetic_ pull toward anchor values.
- It handles RTL, dark mode, and reduced motion, and the thumb has a 44px touch target.
- [Component docs](/components/slider.md) &bull; [Storybook](https://dialtone.dialpad.com/vue/?path=/story/components-slider--default)

## Meet DtSlider

A slider lets users choose a value (or a range of values) by dragging a thumb along a track. It's the right control when the position within a scale matters more than the exact number (the typical examples being volume or brightness, where users aren't looking for a specific, defined value, but rather something that _feels_ right).

A single number as the `modelValue` will result in a single thumb; an array of two numbers will result in two thumbs (and select a range). Try all three below.

```vue demo
<!-- @wrapper -->
<dt-stack gap="400" class="d-w100p">
  <dt-slider :model-value="50" label="Volume" />
  <dt-slider
    :model-value="[20, 70]"
    label="Price range"
    :show-marks="[{ value: 0, text: 'Min $0' }, { value: 100, text: 'Max $100' }]"
    :get-value-text="(value, index) => index === 0 ? `Minimum: $${value}` : `Maximum: $${value}`"
  />
  <dt-slider :model-value="60" label="Brightness">
    <template #start>
      <span role="img" aria-label="dim">🔅</span>
    </template>
    <template #end>
      <span role="img" aria-label="bright">🔆</span>
    </template>
  </dt-slider>
</dt-stack>
```

## Anatomy

A slider has more parts than it seems to, and the rest of this post refers to them by name. Pick one below to highlight it on the live slider.

```vue demo
<!-- @wrapper -->
<dt-stack gap="400" class="d-w100p">
  <div class="anatomy-demo" :data-part="anatomyPart">
    <dt-slider
      v-model="anatomyValue"
      label="Volume"
      suffix="%"
      readout="always"
      :show-ticks="25"
      :show-marks="[0, 25, 50, 75, 100]"
    >
      <template #start>
        <span role="img" aria-label="quiet">🔈</span>
      </template>
      <template #end>
        <span role="img" aria-label="loud">🔊</span>
      </template>
    </dt-slider>
  </div>
  <dt-radio-group v-model="anatomyPart" name="anatomy-part" legend="Highlight a part">
    <dt-radio v-for="part in anatomyParts" :key="part.value" :value="part.value">
      {{ part.label }}
    </dt-radio>
  </dt-radio-group>
</dt-stack>
```

| Part | What it is | Controlled by |
| --- | --- | --- |
| Label | Names the slider for everyone, including screen readers. | `label`, `show-label`, `#label` slot |
| Start and end slots | Optional content at either end of the track (e.g., icons). | `#start`, `#end` |
| Track | The full scale, from minimum to maximum. | n/a (themed with tokens) |
| Indicator | The filled span, from the start, from the end, or from a value you choose. | `fill-origin` |
| Ticks | Small dots along the track that show the step grid or notable positions. | `show-ticks` |
| Marks | Text labels at key positions. | `show-marks` |
| Thumb | What you drag. Its hit area is 44×44px, larger than the visible thumb. | `v-model` |
| Readout | The current value. It's a tooltip by default (shown while the thumb is hovered, focused, or dragged), and sits below the track with `readout="always"`, as it does here. | `readout` |

> [!INFO] Layout
> DtSlider keeps the same vertical rhythm as DtInput and DtSelectMenu, so it stacks with them at a shared gap. It doesn't add outer spacing, so add the gap yourself (e.g., with [DtStack](/components/stack.md)).

## When to use a slider

Use a slider when the exact value matters less than where it sits on a scale: a volume level, a budget cap, a price range.

| If people need to… | Use |
| --- | --- |
| Pick an approximate value from a range (e.g., volume, brightness, a percentage) | DtSlider |
| Filter by a numeric range where precision isn't critical (e.g., price, duration) | DtSlider with two thumbs |
| Enter an exact number | [DtInput](/components/input.md) |
| Choose from a small set of discrete options (about five or fewer) | [DtRadioGroup](/components/radio-group.md) or [DtSelectMenu](/components/select-menu.md) |
| Switch something on or off | [DtToggle](/components/toggle.md) |

When both feel and precision matter, pair the slider with number inputs bound to the same value. This works especially well on touch devices, where dragging to an exact value is harder.

```vue demo
<!-- @wrapper -->
<dt-stack gap="100" class="d-w100p" align="center">
  <dt-slider
    v-model="meetingHours"
    label="Meeting hours"
    :min="8"
    :max="18"
    :show-ticks="1"
    :min-gap-steps="1"
    :get-value-text="(value, index) => `${index === 0 ? 'Start' : 'End'}: ${value}:00`"
  />
  <dt-stack direction="row" gap="100" align="center">
    <dt-input
      v-model.number="meetingHours[0]"
      label-strength="medium"
      label-size="200"
      label="Start"
      type="number"
      :min="8"
      :max="meetingHours[1] - 1"
    />
    <dt-input
      v-model.number="meetingHours[1]"
      label-strength="medium"
      label-size="200"
      label="End"
      type="number"
      :min="meetingHours[0] + 1"
      :max="18"
    />
  </dt-stack>
</dt-stack>
```

## Values, ticks, marks, and snapping

### Ticks and marks

_Ticks_ and _marks_ look related, but they do different jobs. Ticks are small dots along the track that show the grid (or any set of notable positions), while marks are text labels at specific values. Neither limits which values you can pick; `step` does that.

On a fine-grained scale, pair frequent ticks with sparse marks to avoid clutter.

```vue demo
<!-- @wrapper -->
<dt-stack gap="300" class="d-w100p">
  <dt-slider
    :model-value="0"
    label="Balance"
    :min="-100"
    :max="100"
    :show-marks="[{ value: -100, text: '−100' }, { value: 0, text: '0' }, { value: 100, text: '100' }]"
    :show-ticks="25"
  />
  <dt-slider
    :model-value="7"
    label="Rating"
    :min="0"
    :max="10"
    :step="1"
    :show-ticks="1"
    :show-marks="true"
  />
</dt-stack>
```

### Hard and soft constraints

`step` is a _hard_ grid: the thumb can only select its values. `snapPoints` is _soft_: it pulls a dragged thumb toward the values you list (an interval or an array), like snapping to guides or objects in a design tool. 

Snapping only affects dragging, not keyboard navigation.

```vue demo
<!-- @wrapper -->
<dt-stack gap="300" class="d-w100p">
  <dt-slider
    :model-value="62"
    label="Budget cap"
    :min="0"
    :max="100"
    :snap-points="25"
    :show-ticks="25"
    suffix="%"
  />
  <dt-slider
    :model-value="60"
    label="Zoom level"
    :min="10"
    :max="400"
    :snap-points="[25, 50, 75, 100, 150, 200, 300]"
    suffix="%"
  />
</dt-stack>
```

_Drag the first slider toward 25, then try to land on 23._

## The value readout

A slider often needs to show the exact value, but showing it costs space. DtSlider's `readout` prop gives you three options:

- `tooltip` (default): a bubble above the thumb, shown only while the thumb is hovered, focused, or dragged. It reserves no space, which suits forms, toolbars, and any space-constrained interface.
- `always`: a readout below the track that's always visible. Use it when the value should stay legible without any interaction (e.g., dashboards).
- `never`: no readout, for when you render the value yourself elsewhere on the page.

```vue demo
<!-- @wrapper -->
<dt-stack gap="300" class="d-w100p">
  <dt-slider :model-value="48" label="Volume" />
  <dt-slider :model-value="48" label="Volume" readout="always" />
  <dt-slider :model-value="48" label="Volume" readout="never" />
</dt-stack>
```

All readouts format the value the same way you format what's announced to assistive technology. Use `prefix` and `suffix` for simple decoration (e.g., `suffix="%"`), or `getValueText` for anything more specific.

## Accessibility and the native input

We lean on the web platform for form controls whenever we can. Each thumb is a native `<input type="range">`, visually hidden. That means the browser handles accessibility behavior for us:

- The role and value semantics (`role="slider"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow`).
- Tab order and focus.
- The arrow keys, Home, and End, including the swap of left and right in RTL.
- Quantizing to `step` and clamping to `min` and `max`.
- Form behavior: set `name` to include the value in a form submission.

On top of that, we only add what a single native input can't express: two thumbs, and Page Up, Page Down, and Shift + Arrow for larger steps. Give every slider a `label`, and for a range, pass `getValueText` so each thumb is announced distinctly (e.g., "Minimum: $20" and "Maximum: $70").

## What DtSlider does NOT do

- **Precise entry**: There's no number field. Pair the slider with [DtInput](/components/input.md), as shown above.
- **Steps in a flow**: A slider is a form element for numeric input, not a stepper for moving through the stages of a flow (e.g., a wizard).
- **Displaying a value**: This slider is optimized for choosing a value, not to display one (even where showing _proportional_ progress could be helpful e.g., an upload status bar).
- **Seek controls**: This slider isn't built for playback seeking in audio or video, where the control also tracks the current position.

See the [full component documentation](/components/slider.md) for all prop values, demos, and usage guidance.
