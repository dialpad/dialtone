## TLDR

- Use `--dt-size-*` tokens instead of `--dt-space-*` for all dimensional values.
- Use the [Migration Tool](#migration-tool) to automate the replacement.
- `--dt-space-*` tokens still work (aliased to size) but are deprecated.

## Overview

We've consolidated space and size tokens into a unified system. Previously, Dialtone had separate token sets for spacing (`--dt-space-*`) and sizing (`--dt-size-*`), but these contained 143 duplicate values. This created confusion about when to use which token type.

Now, all dimensional values use `--dt-size-*` tokens:

- **Dimensions**: `width`, `height`, `min-width`, `max-height`
- **Spacing**: `padding`, `margin`, `gap`
- **Positioning**: `top`, `left`, `right`, `bottom`
- **Borders**: `border-width`, `border-radius`

This change aligns with the [W3C Design Tokens Community Group (DTCG)](https://tr.designtokens.org/format/) specification, which uses a unified `dimension` type for all such values.

## Why Use the Migration Tool?

The migration tool automates the conversion process with several key benefits:

- **Speed**: Migrate entire projects in seconds instead of manual find/replace
- **Consistency**: Ensures uniform conversion patterns across all files
- **Safety**: Handles all token variants (negative, percent) correctly
- **Accuracy**: No manual transcription errors or forgotten conversions

## Migration Tool

`dialtone-migration-helper` scans your files for `--dt-space-*` patterns and converts them to `--dt-size-*`. It's included with `@dialpad/dialtone-css`.

### Usage

#### Preview Changes

```bash
npx dialtone-migration-helper --cwd ./src
# Select "space-to-size" from the config list
```

The tool will show you each change before applying it. You can review and approve changes interactively.

#### Apply All Changes

```bash
npx dialtone-migration-helper --cwd ./src --yes
# Select "space-to-size" from the config list
```

### What It Migrates

The migration tool handles all space token variants:

| Pattern | Example |
|---------|---------|
| Base tokens | `var(--dt-space-400)` → `var(--dt-size-400)` |
| Negative variants | `var(--dt-space-400-negative)` → `var(--dt-size-400-negative)` |
| Percent variants | `var(--dt-space-50-percent)` → `var(--dt-size-50-percent)` |

### File Types Processed

The tool scans these file types:

- **Stylesheets**: CSS, LESS, SCSS, SASS, Stylus
- **Templates**: HTML, Vue, Markdown
- **Scripts**: JavaScript, TypeScript, JSX, TSX

## Manual Migration

For small changes or if you prefer manual migration, use find/replace:

**Find:** `--dt-space-`

**Replace:** `--dt-size-`

This simple replacement works because all space tokens have identical size equivalents.

## Backwards Compatibility

<dt-notice
  kind="info"
  class="d-wmx100p d-mt24 d-mb24"
  hide-close
>
  <strong>No breaking changes yet.</strong> All <code>--dt-space-*</code> tokens continue to work. They are now aliases that resolve to their <code>--dt-size-*</code> equivalents.
</dt-notice>

However, we plan to remove the space token aliases in **v10.0** (the next major version). Migrating now ensures your code won't break when that happens.

## Why This Change?

### DTCG Compliance

The [Design Tokens Community Group (DTCG)](https://tr.designtokens.org/format/) specification defines a unified `dimension` type for all values that represent sizes, lengths, or distances. Separating "space" from "size" was a Dialtone-specific distinction that didn't align with this standard.

### Simpler Mental Model

Previously, you had to decide:
- "Is this a spacing property? Use `--dt-space-*`"
- "Is this a sizing property? Use `--dt-size-*`"

Now there's one answer: **Use `--dt-size-*` for all dimensional values.**

### Reduced Redundancy

We eliminated 143 duplicate tokens. The same values existed in both `space` and `size` token sets, which:
- Increased bundle size unnecessarily
- Created confusion about which to use
- Made maintenance harder

## Summary

| Aspect | Details |
|--------|---------|
| **Action Required** | Replace `--dt-space-*` with `--dt-size-*` |
| **Tool** | `npx dialtone-migration-helper` → select "space-to-size" |
| **Breaking?** | No, space tokens are aliased (for now) |
| **Removal Timeline** | v10.0 will remove `--dt-space-*` aliases |
